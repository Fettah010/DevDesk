## 1. Goal

A developer selects a repository from the template catalog (initially `DevTem Win UI
3` only), enters a name and location, previews exactly what will be created, and
presses **Create**. The new app folder builds with 0 errors, commits once, and the
runner can open it in Explorer or VS. DevDesk never mutates the template.

This is job **J6** ("start something new") and it lands on top of the proven
process/safety layer from v0.3.0 so recursive copy + token replacement is never
destructive or silent.

Exit state of this version, in one sentence: *from an empty target folder a user
creates `TryApp`, watches the preview, builds it, runs it, and the template repo
is untouched.*

## 3. Decisions this work order resolves

| ID | Decision | Why |
|---|---|---|
| **D-0.4.1** | **Template immutability.** Target must be outside template; hash template tree before/after in tests; refuse if template inside target. | Roadmap §2.8: template is read-only, copy-only. A copy that touches its own source is destructive. |
| **D-0.4.2** | **One way to create.** No overwrite/rename-over-exists; deterministic binary-safe copy with rollback. | An overwrite losing an existing project is user-facing data loss; rollback is mandatory for safety. |
| **D-0.4.3** | **User-controlled location.** Name must be identifier-safe (`[a-zA-Z_][a-zA-Z0-9_]*`), existing folder blocked, path length checked, drive space warned, last location remembered. | Scaffolding into a bad name or full disk fails silently; up-front validation is cheap honesty. |
| **D-0.4.4** | **Safe token substitution.** Symbols for app name, safe name, root namespace, assembly name, exe name, app id, pack title/authors, repo URL, window subtitle, version `0.1.0`; marker-level replacement per file pattern (`*.csproj`, `App.xaml`, scripts). | Hardcoded literals are the main failure mode; every replacement must be planned before copy. |
| **D-0.4.5** | **Dry-run UI.** Preview tree matches the actual result byte-for-byte; no editing tokens in preview; banner "copy only, template untouched". | A preview that doesn't match the result is a lie; editability breaks the contract. |
| **D-0.4.6** | **Post-create chain.** Optional `git init` + first commit (author `DevDesk <no-reply@devdesk.io>`), smoke `dotnet build`, open in Explorer/VS, "run it" handoff to v0.3.0 BuildService. | Build badge only if it actually builds; handoff avoids duplicating build logic. |
| **D-0.4.7** | **Wizard UX.** 4 steps: template → name/location/options → preview → result; validation blocks with a reason; back/forward preserves input; disabled buttons need visible reasons. | A wizard without validation is noise; a disabled control without text is never read (gotcha 12). |

## 5. Contracts

### 5.1 `TemplateDescriptor`

```csharp
public sealed record TemplateDescriptor(
    string Name,
    string Description,
    string Version,
    string FullPath);
```

### 5.2 `ITemplateService`

```csharp
public interface ITemplateService
{
    Task<IReadOnlyList<TemplateDescriptor>> ListAvailableTemplatesAsync();
    Task<WizardResult> RunWizardAsync(CreateRequest request);
}

public sealed record CreateRequest(
    TemplateDescriptor Template,
    WizardInputs Inputs);

public sealed record WizardInputs(
    string Name,
    string Location,
    WizardOptions Options);

public sealed record WizardResult(
    string TargetPath,
    BuildResult BuildInfo,
    GitResult? GitInfo = null);
```

**Rules:**

1. Names must be identifier-safe (`[a-zA-Z_][a-zA-Z0-9_]*`).
2. Target location must be outside the template root.
3. Dry-run matches preview exactly; cannot create before preview confirmation.
4. Binary-safe copy: no partial write, path-guard, progress per file, cancel rollback.
5. Post-create: optional `git init` + first commit; smoke `dotnet build` with the
   same profile resolution as an existing project; build badge only if `0` errors.

### 5.3 Persistence

No new persistent files at v0.4.0 beyond the user's target app folder. Template
descriptors are cached in memory for the session (no disk cache yet — 0.5 adds
that for GitHub data).

## 6. UX

### 6.1 Templates page

- **Catalog:** one row per template: name, description, version, icon if
  available; "New app" primary action per row.
- **Wizard:** 4 steps:
  1. **Template** — pick from catalog; shows markers found and icon.
  2. **Name / location** — identifier-safe name, location picker with remembered
     last folder, existing-folder and path-length validation.
  3. **Preview** — tree of created/renamed files + per-file replacements; banner
     "Template is read-only — only the target is written."
  4. **Result** — created path, build status (in progress / succeeded / failed),
     links: Open in Explorer, Open in VS, Run build (handoff to v0.3.0).
- Validation errors appear inline with a reason, never a silent block.

### 6.2 State matrix

| State | UI contract |
|---|---|
| Loading | ring + "Loading templates…" |
| Empty | no templates found + action that would create one |
| Idle | catalog rows, each with "New app" |
| Wizard step | 1-4 progress; back/forward preserve input |
| Creating | progress per file; cancelable; "N files copied" |
| Success | path + build badge + open links |
| Failure | what failed, reason, Open log, retry from same step |

## 11. Risks

| Risk | Mitigation |
|------|------------|
| Path traversal / template inside target | Hash compare before copy; refuse early with sentence |
| Windows path length | normalize, warn, suggest external location |
| AV / lock files | retry with clear message; progress per file |
| Template drift (missing marker) | descriptor validation; warn during dry-run; block rename |
| Drive space shortage | check before copy; warn with estimate |
