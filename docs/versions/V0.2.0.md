## Goal

Make routine Git state visible in Projects and provide carefully previewed Git
write operations, while keeping repository scans local and read-only. Every
operation must use argument-list process invocation, cancellation, bounded
timeouts, and understandable errors. The DevDesk app itself does not use GitHub
APIs; its Git actions work with any remote.

## Explicit boundaries

- No force push, hard reset, starting a rebase, interactive/hunk staging,
  submodule or stash management, or GitHub PR/release UI inside DevDesk.
- Build remains disabled until v0.3.0. Existing scan behavior remains read-only.
- No write operation starts without showing its actual target and risk-appropriate
  confirmation. Network operations are always explicit.
- Keep all new tests in `DevDesk.Tests/`. Use disposable repositories only.

## Verification and exit demo

Run `Scripts/ci.ps1` after implementation (Release x64 build and full suite), then
`Scripts/smoke-ui.ps1` and `Scripts/verify-shell.ps1`. Review the Projects page at
normal and narrow window sizes, light and dark themes, and with keyboard
navigation. On a scratch clone: edit a file, stage one file, commit with amend
preview, create and switch branches, pull, push, open in VS, then cancel a
discard preview and verify the file is unchanged.

## Decisions resolved for this work order

- Version and channel are `0.2.0-beta` and `beta`, following the roadmap.
- No Git operation is allowed to block the UI thread.
- Authentication uses the user's existing Git credential helper; Git prompts
  are disabled inside DevDesk, and the UI explains how to authenticate externally.
- The app and tests never create commits, tags, or pushes. Repository delivery
  and the separately requested scheduled release are handled through GitHub.
