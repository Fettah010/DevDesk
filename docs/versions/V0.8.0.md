## 1. Goal and release boundary

Transform DevDesk from a mouse-driven dashboard into a fast, keyboard-first,
always-available command center without destabilizing the core read-only scan
and safety architecture established in v0.1–v0.7.

A user working on multiple repositories needs to trigger common operations
(jump to project, build, run, commit, push, release, open in VS/Explorer, scan)
in fewer than three keystrokes. Long-running operations must report their status
via subtle activity badges and in-app completion toasts without forcing the user
to remain on the Activity page. When minimized, DevDesk can optionally rest in
the system tray and run periodic, offline-only health audits that alert the
developer to uncommitted changes or divergent branches across their workspace.

### 1.1 The v0.8.0 boundary

This release covers the six roadmap work items **W-0.8.1 through W-0.8.6**:
1. **`CommandRegistry`**: Single source of truth for all application actions,
   icons, titles, shortcuts, and execution/enablement predicates.
2. **Command palette (`Ctrl+K`)**: Modal overlay with fuzzy search, grouped
   results, recency weighting, and keyboard navigation.
3. **Global keyboard accelerators & help (`F1`)**: Comprehensive accelerator
   map, startup conflict detection, discoverable tooltips, and shortcut guide.
4. **Activity center v2 & notification toasts**: Shell badge counters,
   transient in-app completion toasts with quick actions (Open Log, Retry, Copy Error),
   and native Windows completion toasts when backgrounded.
5. **System tray & background health monitor (opt-in)**: Tray icon with context
   menu, minimize/close-to-tray lifecycle, and local-only periodic Git health
   checks with deduplicated change notifications.
6. **Unified context menus**: Real right-click context menus on project cards
   and list items bound directly to the `CommandRegistry`.

### 1.2 Boundary defense and non-goals

To prevent scope creep and maintain release discipline:
- **No v0.9 overstepping**: Do not perform the full accessibility audit,
  motion pass, full `.resw` / `x:Uid` string externalization, onboarding welcome
  card, or package distribution overhaul. v0.8 adds accessible names and focus
  handling to its own new controls only.
- **No v1.0 overstepping**: Do not freeze public API contracts, create code
  signing pipelines, or alter the default channel to stable.
- **No scripting or plugin engine**: Commands are statically registered C#
  action descriptors. Do not build an external Lua/JS scripting runtime or
  macro recorder.
- **No global Windows hotkeys outside the app**: Do not register system-wide
  low-level keyboard hooks (e.g. `RegisterHotKey` for system-wide `Ctrl+Alt+D`).
  Accelerators function only when DevDesk has keyboard focus; tray activation
  uses standard Windows notification area conventions.
- **No background network activity**: Background health monitoring executes
  local-only, read-only Git status inspections (`git status --porcelain=v2`,
  `git rev-parse`). It must never call `git fetch`, `git pull`, or GitHub APIs.
- **No LLM/AI chat prompts**: All commands remain deterministic and explicit.

### 1.3 Exit demo

1. Open DevDesk via desktop shortcut; press `Ctrl+K` to open the palette in under 50 ms.
2. Type `form` — see `Formixa` project actions ranked first. Use arrow keys to
   select `Build Formixa` and press `Enter`.
3. Press `Ctrl+,` to jump immediately to Settings without touching the mouse.
4. While in Settings, observe the title bar / shell activity indicator showing
   the running build. Upon completion, an in-app toast notification announces
   the outcome with clickable `Open Log`.
5. Press `F1` to display the keyboard shortcuts help overlay; dismiss with `Esc`.
6. Enable "Minimize to tray" and "Background health check" in Settings.
7. Minimize the window — the app retreats to the system tray. A local scratch
   edit in a monitored repo triggers an offline notification only once.
8. Double-click the tray icon or press `Win+B` / tray menu to restore DevDesk.

## 2. Research findings and current-state constraints

| Area | Current state in checkout | Design consequence for v0.8.0 |
|---|---|---|
| **Command handling** | Actions are wired as XAML event handlers (`Click`, `ItemInvoked`) and ad-hoc `RelayCommand` instances scattered across view models. | Introduce `CommandRegistry` in `Services/` as a centralized registry. Existing UI controls and the command palette must consume the same `AppCommand` instances. |
| **Keyboard accelerators** | Zero `KeyboardAccelerator` elements in `MainWindow.xaml` or pages. Tab order and basic keyboard navigation work, but global shortcuts do not exist. | Define a unified `KeyboardAccelerator` table in `MainWindow`. Route global shortcuts (`Ctrl+K`, `Ctrl+R`, `Ctrl+,`, `Ctrl+1..8`, `F1`) to `CommandRegistry`. |
| **Activity monitoring** | `ActivityCenter` manages an internal queue, serialized builds, and an in-memory history of 200 items, but only `ActivityPage` renders it. | Extend `ActivityCenter` with event-driven badge counters (running, failed) and a notification pipeline (`IOperationNotificationService`). |
| **Window & single instance** | `SingleInstance` uses `Microsoft.Windows.AppLifecycle.AppInstance` with `RedirectActivationToAsync` to hand activation to the running window. | Integrate tray icon restore with `SingleInstance`. When the window is hidden in the tray, redirection or tray double-click must invoke `MainWindow.BringToFront()`. |
| **Settings schema** | `AppSettings.cs` already contains `FeatureSettings` with `BackgroundHealthCheck` and `MinimizeToTray` booleans (`schemaVersion: 1`). | No schema bump required. Surfacing these settings in `SettingsPage.xaml` and binding them to the tray and health services is purely additive. |
| **Project navigation** | Navigation uses `ContentFrame.Navigate(PageFor(route))` with string tags in `Routes.cs`. | Command palette navigation commands can directly dispatch through `NavigationService` / `MainWindow.Navigate()`. |
| **Search engine** | `ProjectListQuery` in `Services/` provides in-memory text tokenization, prefix matching, and tag filtering. | Reuse the matching logic for command palette keyword and project ranking. Keep palette query execution in-memory (< 20 ms). |
| **Context menus** | Dashboard project cards have a minimal two-item `Flyout` (Open in Explorer / Visual Studio). Detail pages have buttons. | Replace card flyouts with a full `MenuFlyout` exposing project-level actions (Build, Run, Open, Commit, Release, Copy Path, Pin) powered by `CommandRegistry`. |
| **Notifications** | Serilog logs events to disk and ring buffer; errors show on-page `InfoBar`. No desktop toast infrastructure exists. | Implement an in-app transient toast container and an optional OS toast bridge using `Microsoft.Windows.AppNotifications` or shell fallback. |

### Confirmed decisions

1. **`CommandRegistry` as a singleton service**: Registered in `AppServices`,
   instantiated during startup before UI page navigation.
2. **In-app palette overlay**: Built as a XAML modal overlay in `MainWindow.xaml`
   (Popup or root Grid layer) with focus trapping, rather than a separate HWND.
3. **PInvoke-backed NotifyIcon**: WinUI 3 in Windows App SDK 2.6 has no official
   first-party `SystemTrayIcon` XAML control. Use a lightweight, clean Win32
   `Shell_NotifyIconW` wrapper in `Infrastructure/Tray/` with window message
   handling on the existing `MainWindow` HWND or dedicated message-only window.
4. **Health check isolation**: Run on a low-priority thread via `TimeProvider`
   timer. Checks inspect Git index and branch heads only; no network operations.
5. **Headless testability**: All command registry resolution, fuzzy search
   scoring, shortcut conflict detection, and health deduplication logic must be
   100% unit-testable without a visible window.

## 4. Proposed contracts and behavior

### 4.1 Command registry architecture (`Services/CommandRegistry.cs`)

`CommandRegistry` is a thread-safe catalog of executable commands.

```csharp
public enum CommandCategory
{
    Navigation,
    ProjectAction,
    BuildAndRun,
    GitAndRelease,
    SystemAndTools
}

public sealed record CommandShortcut(VirtualKey Key, VirtualKeyModifiers Modifiers)
{
    public override string ToString()
    {
        var parts = new List<string>();
        if (Modifiers.HasFlag(VirtualKeyModifiers.Control)) parts.Add("Ctrl");
        if (Modifiers.HasFlag(VirtualKeyModifiers.Shift)) parts.Add("Shift");
        if (Modifiers.HasFlag(VirtualKeyModifiers.Menu)) parts.Add("Alt");
        if (Modifiers.HasFlag(VirtualKeyModifiers.Windows)) parts.Add("Win");
        parts.Add(Key.ToString());
        return string.Join("+", parts);
    }
}

public sealed class AppCommand
{
    public required string Id { get; init; }
    public required string Title { get; init; }
    public string? Description { get; init; }
    public required CommandCategory Category { get; init; }
    public IReadOnlyList<string> Keywords { get; init; } = Array.Empty<string>();
    public string? Glyph { get; init; }
    public CommandShortcut? DefaultShortcut { get; init; }
    public Func<bool>? CanExecutePredicate { get; init; }
    public required Func<object?, Task> ExecuteAsync { get; init; }

    public bool CanExecute() => CanExecutePredicate?.Invoke() ?? true;
}
```

#### Core command registration inventory

1. **Navigation**: `nav.dashboard` (`Ctrl+1`), `nav.projects` (`Ctrl+2`),
   `nav.templates` (`Ctrl+3`), `nav.github` (`Ctrl+4`), `nav.self` (`Ctrl+5`),
   `nav.activity` (`Ctrl+6`), `nav.settings` (`Ctrl+,` / `Ctrl+7`), `nav.diagnostics` (`Ctrl+8`).
2. **Operations**: `catalog.scan` (`Ctrl+R` / `F5`), `palette.open` (`Ctrl+K`),
   `help.shortcuts` (`F1`), `tools.exportLogs`, `tools.clearCache`.
3. **Project actions**: `project.build` (`Ctrl+Shift+B`), `project.run` (`Ctrl+Shift+R`),
   `project.openExplorer`, `project.openVs`, `project.changes`, `project.commit`,
   `project.release`, `project.pin`, `project.copyPath`.

### 4.2 Command palette UX & ranking (`Controls/CommandPalette.xaml`)

- **Presentation**: Centered modal overlay (width: 640 px, max height: 480 px)
  with a search box, category tabs/filters, and a virtualized results list.
- **Backdrop**: Layered over page content with a semi-transparent scrim
  (`LayerOnMicaBaseAltFillColorDefaultBrush`) that dismisses on click or `Esc`.
- **Ranking algorithm**:
  1. Exact prefix matches on command title or project name receive highest score.
  2. Substring matches on title or keyword receive second-tier score.
  3. Fuzzy sequence matches (characters appearing in order) receive third-tier score.
  4. Recent usage boost: Recently executed commands and recently opened projects
     from `ProjectOrganizationStore` receive a tie-breaking score bonus.
- **Dynamic project expansion**: Typing a project name (e.g. `DevDesk` or `Formixa`)
  yields the project itself (to navigate) as well as its direct actions
  (`Build DevDesk`, `Run DevDesk`, `Open DevDesk in VS`, `Commit DevDesk`).

### 4.4 Activity center v2 & notification toasts

- **Badge indicators**:
  - Title bar displays an active task indicator when background operations are
    running (e.g., `● 1 building...`).
  - NavigationView footer item for `Activity` displays an `InfoBadge`: blue
    numeric badge for active tasks, red badge if recent failures are unviewed.
- **In-app toast container**:
  - Located in the bottom-right corner of `MainWindow`.
  - Non-intrusive transient card (auto-dismiss after 6 seconds).
  - Displays operation icon, title, completion status, elapsed duration, and
    action buttons:
    - On Success: `Open Output` (if publish/build), `Dismiss`.
    - On Failure: `Open Log`, `Retry`, `Copy Error`.
- **System toast bridge**:
  - When the app window is minimized or inactive, completion notifications
    can be dispatched to the Windows Action Center via Windows App SDK
    `AppNotificationManager`.
  - Clicking the notification activates and restores the window to the
    relevant repository or Activity log.

### 4.5 System tray lifecycle (`Infrastructure/Tray/SystemTrayService.cs`)

- **Win32 notification area icon**:
  - Implemented via `Shell_NotifyIconW` with `NIM_ADD`, `NIM_MODIFY`, `NIM_DELETE`.
  - Icon matches app state: standard sea-blue app icon normally; subtle dot
    when operations are actively running.
  - Tooltip: `DevDesk — X repositories monitored`.
- **Context menu**:
  - `Open DevDesk` (default double-click action).
  - `Run Scan` (triggers background refresh).
  - Separator.
  - `Exit` (terminates application gracefully, cancelling pending operations).
- **Window lifecycle integration**:
  - When `AppSettings.Features.MinimizeToTray` is true:
    - Clicking window minimize button (`SW_MINIMIZE`) or close button (`WM_CLOSE`)
      hides the native HWND (`ShowWindow(hwnd, SW_HIDE)`).
    - Double-clicking the tray icon restores the window (`ShowWindow(hwnd, SW_RESTORE)`
      and `SetForegroundWindow(hwnd)`).
  - When `MinimizeToTray` is false:
    - Standard Windows minimize and exit behavior is preserved.

### 4.6 Background health check & deduplication

- **Timer**: `PeriodicTimer` or `TimeProvider.CreateTimer()` running in `BackgroundHealthMonitor`.
- **Cadence**: Default 15 minutes (configurable in Settings: 15 / 30 / 60 min).
- **Execution**:
  - For each enabled root in `AppSettings.Roots`, query the repository list from `ProjectCatalog`.
  - Execute quick local Git queries:
    - `git status --porcelain=v2 -unormal` (dirty state)
    - `git rev-parse --abbrev-ref HEAD` (current branch)
    - `git rev-list --left-right --count HEAD...@{u}` (ahead/behind upstream)
  - Compute a 64-bit or SHA-256 state hash for the repository:
    `Hash(Branch, DirtyFileCount, AheadCount, BehindCount)`.
- **Deduplication**:
  - Compare with the previously recorded state hash.
  - If identical: take no action.
  - If state transitioned from clean to dirty or commits are behind/ahead:
    record new hash and publish an in-app health update.
  - If window is hidden, emit at most one coalesced notification summary
    (e.g., *"3 repositories have uncommitted changes or divergent branches"*).
  - Strictly zero network calls: Git queries use local metadata only.

## 7. Performance and reliability gates

| Metric | Target | Verification Method |
|---|---|---|
| **Palette open latency** | < 50 ms | `Stopwatch` measurement from `Ctrl+K` keypress to popup render |
| **Palette query filter latency** | < 20 ms | In-memory query timer across 100 commands + 50 projects |
| **UI thread blocking** | < 50 ms (M6) | Monitored via existing `UiThreadHeartbeat` and `PerfCounters` |
| **Background health check duration** | < 500 ms per root | Timed during local git status iteration; runs off UI thread |
| **Tray memory footprint** | Negligible (< 2 MB) | Process working set comparison when minimized vs open |
| **Zero network calls during health checks** | 0 requests | Enforced by design; Git commands use local flags only |

## 8. Risks and mitigations

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| **Shortcut collision with Windows/VS** | Medium | Medium | Limit global shortcuts to standard WinUI accelerator patterns (`Ctrl+K`, `Ctrl+Shift+B`). Avoid overwriting basic input keys. Run `KeyboardMapTests` conflict detection. |
| **Tray icon orphan on unexpected crash** | Low | Low | Call `Shell_NotifyIconW(NIM_DELETE)` in `App.xaml.cs` unhandled exception handler and `MainWindow_Closed`. |
| **Background health check disk contention** | Low | Low | Run health checks sequentially at low thread priority with cancellation support. Respect existing `ScanEngine` locks. |
| **Palette UI stutter on initial load** | Medium | Low | Pre-warm command registry and icon glyph caches during app startup after native window visibility. |
| **Notification spam from background health** | Medium | Medium | Strictly deduplicate notifications using state hashes. Notify at most once per repo per state change. Coalesce multiple repo changes into one summary toast. |

| **D-0.8.1** | Use an in-window modal overlay for Command Palette instead of a second HWND. | Accepted | Simpler window lifecycle management, seamless Mica/Acrylic styling, natural focus trapping, zero multi-window placement bugs. |
| **D-0.8.2** | Use Win32 `Shell_NotifyIconW` PInvoke for system tray integration. | Accepted | Windows App SDK 2.6 does not provide an official out-of-the-box XAML tray control for unpackaged apps. A focused Win32 interop class is robust and lightweight. |
| **D-0.8.3** | Keep background health checks strictly offline and read-only. | Accepted | Preserves DevDesk's core local-first principle. Scans and health checks must never touch the network or mutate git repositories. |
| **D-0.8.4** | Deduplicate background health notifications via state hashing. | Accepted | Prevents notification spam while the application runs minimized in the background. |
